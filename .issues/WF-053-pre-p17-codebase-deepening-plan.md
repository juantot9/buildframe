## Destination

Every confirmed problem in the codebase is written down in one ledger, ranked, and carrying a decided disposition—fix, accept, defer, or deletion-bound—with the general policy questions the audit raises answered as well. When this map closes, the **Deepen the active Modules**, **Review the legacy packages for blockers**, and **Pass the codebase deepening quality gate** packages of [Design the solo-developer execution plan](./WF-051-design-solo-developer-execution-plan.md) can be carried out without anyone inventing a rule mid-change. No code changes on this map.

## Notes

- This map decides; [Design the solo-developer execution plan](./WF-051-design-solo-developer-execution-plan.md) executes. Nothing here changes code.
- This effort exists because [Chart the Neoflow v1 implementation plan](./WF-039-neoflow-v1-implementation-plan.md) explicitly ruled evidence-dependent optimization and simplification choices out of its own scope and named a fresh planning effort as the mechanism for them. This is that effort, not a second route over the same ground.
- The finding ledger is `docs/audit/pre-p17-codebase-findings.md`—the single artifact shared with the **Audit architecture and risk across every package** package of the execution plan. Findings are written to it as they are confirmed, never held until the end; a crashed session already lost roughly thirty minutes of analysis by holding it all in context.
- Improvements must be evidence-driven. No speculative abstraction, no style-only churn, no new shallow Interfaces. A finding supported only by taste is dispositioned **accepted**, not **fixed**.
- `CONTEXT.md` is the canonical vocabulary authority. Tests exercise each Module through its Interface.
- Gate A production correction and Gate B source promotion are closed and passed. Do not re-run either. `HANDOFF.md` §"Gate status" is their durable record; their raw logs were deliberately kept out of this repository and are perishable.
- The unverified leads recovered from the crashed session have been worked and deleted from [Audit architecture and risk across every package](./WF-054-audit-architecture-risk-every-package.md), surviving only in git history. Its resolution comment records what was confirmed and what was ruled out; roughly half did not survive confirmation, so treat any lead reached for later with the same skepticism.
- Use `/grilling` and `/domain-modeling` for the decisions here, and `/research` only for a fact outside this working directory. `/simplify` and `/code-review` belong to execution, not to this map.
- **How the disposition phase is cut, decided while charting it on 2026-08-07.** One ticket per owning Module, in the order **P16C** already fixes—Workspace, Local Runtime, Pi Adapter, Neoflow Application, then root scripts and configuration—with legacy folded into the last one on size, plus a do-first ticket ahead of them all and the vocabulary question held separately. Three facts made this the shape rather than a preference. The ledger's **cross-cutting** and **security** sections are filing categories, not clusters: every one of their 16 findings names a single owning Module, so they need no tickets of their own. **Ranking is therefore within a package**, because **P16C** fixes the cross-package order already, and the only cross-package scheduling act left to this map is the do-first pull-forward. And one ticket over all 46 would compact mid-pass, which is where a ratification stops being read—the findings arrive carrying a proposed disposition, so the work is confirming or overturning 46 arguments, not inventing them.

So the repair narrows (the "stop killing" half is withdrawn) while the regression test hardens: ≥1,600 **object ids** plus a forced early exit, since a test built from the existing fixture would pass against unfixed code. **W-14**'s causal claim now has a count instead of an impression — the full v1 suite spawns **1,034 `git` processes**, ~790 production and 244 harness, worth ~36 s of added latency on 26.6.0 against a 17.2 s suite, corroborating WF-056 without re-running it — but its **proposed fix cannot answer its own open question**, because "both call sites" leaves eight bare-word test-helper sites untouched and the finding's own evidence gate is a full suite run. - [Disposition the Workspace reviewing and diff findings](./WF-073-disposition-workspace-reviewing-and-diff-findings.md) — **all five `fixed`, one pulled ahead, and two findings turned out to be wrong about their own repair rather than their own evidence.** The new rule: **where a finding proposes two repairs as alternatives, that is a claim, and claims fail.** **W-10** joins its two fixes with "or" and they differ by **4–11×** — benchmarked at `MAX_LCS_CELLS`, the current double `Buffer.from` costs 422 ms, the finding's *view* rewrite 381 ms (1.11×), and a direct `Uint8Array` compare 34 ms (12.4×, zero heap delta), because the cost is Buffer *object construction*, not the byte copy. The view — the more surgical-sounding option, described in most detail — recovers a tenth of the win, so it is **withdrawn from the proposal**. **W-13**'s hazard *does not compile*: its stated mechanism, that a moved `sha256(a, b)` "keeps compiling and quietly digests only `a`", is false (`TS2554`, exit 2), though the runtime collapse is real. The genuine silent path is that **a unary function satisfies a variadic type**, so the Workspace `sha256` satisfies the Pi Adapter's contract while not honouring it — which forces the shared helper's multi-part form to take an **array**, not varargs, or the fix reopens the hole. Its digest-related severity was corrected to low; the later codec decision separately raises W-13's validation half to medium. **X-03 exposed a boundary error between two findings**: sweeping every `JSON.stringify` found three *durable* comparison sites — a fresh stringify against one persisted in Authoritative State, deciding whether a replayed command is the same command — belonging to neither X-03's in-process pairs nor **X-01**'s digests, because the two findings partitioned the hazard **by syntax rather than by mechanism**. Probed, not argued: the two sibling normalizers disagree, `reviewing.ts` rebuilding from a literal while `harnessInteraction.ts` preserves caller key order through `structuredClone` and spread, so a replay can be told its already-committed command was an identity reused for a different one. Kept at **low** because `commandIdentity` is a fresh UUID so it is unreachable today — with the condition that would reach it named rather than implied, since inflating an unreachable path is the error W-07's correction warned against. **W-11** holds and understates itself twice (the limit is reached exactly when the LCS is *skipped*; the precheck is tighter than proposed, with no context term; and each discarded row cost a `sha256`). **W-12**'s "roughly twenty" is 21 across **seven** files, two named sites are not the codec at all, and three real ones are missing — W-14's error again, a fix scope narrower than the finding's subject. **The deferral question was one question, not five**: **P16B does not rewrite this code, it re-runs it**, so nothing defers and W-10's pull-forward follows, since P16C depends on P16B and would otherwise ship continuous re-diffing over the unfixed path. All three cross-package obligations are recorded — the Pi Adapter owns `markerMatches` and inherits the array-form digest contract, and X-01 is told not to assume it covers the durable sites. **W-13 is the first finding whose completeness claims all survive intact** (5/4/4/2/4). Ledger now **18 of 46**.
