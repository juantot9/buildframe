## Operating contract

- Run **one package at a time** in the order below. A learning gate may send work back to the owning package; it never opens a parallel feature stream.
- Keep the repository buildable at every package. Until the hard cutover, verify the dependency-isolated legacy MVP and v1 source island independently.
- A package is one reviewable outcome, normally one focused coding-agent session. Split it before coding if its listed acceptance evidence cannot be produced without loading another package's implementation details.
- Reload only this plan card, its linked authority, the owning Module directory, directly blocking package results, and named fixtures. Do not reload the whole blueprint.
- Tests cross the owning **Interface**. Private parser or viewport tests survive only where they protect unusually lossless mechanics. No caller receives persistence, Git, IPC, or native-host composition primitives.
- Every semantic command has one owner, one expected state version, and one stable command identity. Its complete transition Durable-Commits before any external effect. No package introduces automatic replay.
- Every package leaves: passing affected fast checks, its named full/risk evidence, a short result note, and no unexplained temporary compatibility path.
- Package numbers are scan aids only; dependencies below always name the package.

## Walkthrough of the default route

1. **A clean starting point exists before code moves.** Prototype evidence is preserved off the production branch, release coordinates are not left as a late surprise, and the v1 graph cannot import the MVP.
2. **The risky shared spine is made real once.** Workspace Identity, SQLite authority, generations, runtime lifecycle, semantic IPC, and owner-local verification exist before a workflow claims to be production-shaped.
3. **The first user value is narrow but honest.** Current-change Reviewing reaches Pi Questions, human dispositions, and Results through real State, runtime, TUI, and Harness seams. The human dogfood gate happens before breadth.
4. **The proven spine is deepened before breadth is added.** After the first dogfood gate, one read-only audit of every package precedes the deferred Live Changes semantics, per-package deepening of the active Modules, and a blocker-only legacy review. Improvements are evidence-driven, and no finding is left unclassified when the gate closes.
5. **Legacy deletion is earned, not postponed indefinitely.** Only after dogfood and exact legacy import evidence does one package remove every legacy product path. User data is never part of that deletion.
6. **Reviewing is finished depth-first.** Evidence breadth, context, Annotation authority, re-review, each Harness route, and Neovim are completed in owner-local packages and walked through before Planning opens.
7. **Planning reuses rather than forks the spine.** Planning adds only its owning records and transitions plus its specific Pi result and Claude Native Gate behavior. It cannot branch on Harness names or reuse Review lifecycle abstractions.
8. **Composition comes after both anchors stand alone.** Plan-to-Review, continuation, bundles, organization, Home and Resume, and saved comparison add relationships and projections without making either anchor depend on the other.
9. **Packaging judges the installed product.** Diagnostics and docs precede separate application and integration assemblies; clean installs, migration and rollback, then human qualification run against immutable `next` artifacts before those exact bytes are promoted.

## Safe deletion ledger

- **Before P18 — Hard-cut the legacy product source:** delete nothing user-facing from the MVP. Copy only audited mechanics and still-valid tests into new owners.
- **At P18 — Hard-cut the legacy product source:** delete all legacy product source, package seams, commands, Mock, Ink/React, one-shot Neovim path, compatibility aliases, and obsolete tests in one coordinated change. Never delete `.neoflow/review.json`, legacy receipt files, v1 State, or evidence branches.
- **After each transplant:** delete the donor test only when an equal or stronger test crosses the new owning Interface; retain narrow parser and viewport tests only when they protect lossless behavior not visible cheaply at that Interface.
- **Before release assembly:** production main contains no disposable implementation probes. Their captured evidence branch remains the primary source; package assembly independently excludes all planning, issues, and fixtures not intentionally shipped.
