## Question

What concrete mechanics, tests, dependencies, and operational assumptions in the current repository remain credible evidence or transplant candidates for the v1 blueprint; what legacy concepts and seams should be deleted rather than carried forward; and what factual build, platform, integration, and data constraints must the target Module architecture account for before that architecture is chosen?

## Resolution comment

The repository confirms the disposition in [Reconcile the current MVP with the blueprint](./WF-016-reconcile-current-mvp.md): it is a tested parts bin, not an architectural base. No current package or product Module has an Interface deep enough or semantically aligned enough to survive. Reuse means transplanting a narrow implementation mechanic and its still-valid tests behind a blueprint-owned Interface; it never means preserving the current owner, import graph, record shape, or caller orchestration.

`pnpm verify` passed on the audited checkout under Node `24.18.0`, pnpm `11.10.0`, Git `2.51.2`, and arm64 macOS. It ran 20 serial assertion scripts (455 `node:assert` calls), strict typechecking, clean ESM builds, CLI help smoke, and compiled-module imports. That establishes a healthy starting checkpoint, not product or cross-platform validation.

### Credible mechanics and regression seeds

- **Git invocation and basic patch parsing.** [`packages/core/src/git.ts`](../packages/core/src/git.ts) usefully fixes locale, disables pagers, color, external diff and text conversion, fixes diff formatting options, includes staged and unstaged tracked changes, discovers non-ignored untracked files, handles unborn `HEAD`, and enforces a byte bound. [`apps/tui/src/diffFormatting.ts`](../apps/tui/src/diffFormatting.ts) recognizes modified, added, deleted, renamed, copied, mode-only, binary, quoted-space, and UTF-8-path patches while preserving old/new line coordinates. Their tests exercise a real temporary Git repository and parser edge cases. These are candidate internal mechanics for a workspace-evidence Adapter and a Review renderer, not a candidate `getGitDiff` Interface: one live `HEAD` patch is not a Change Set or Review Snapshot.
- **Side-aware diff presentation and navigation.** [`apps/tui/src/review/anchors.ts`](../apps/tui/src/review/anchors.ts), [`apps/tui/src/changes/diffViewport.ts`](../apps/tui/src/changes/diffViewport.ts), and [`apps/tui/src/changes/navigation.ts`](../apps/tui/src/changes/navigation.ts) contain tested mechanics for distinct old/new/context targets, excerpt-assisted relocation, wrapped visual rows, stable viewport positioning, selection retention across refresh, page movement, target traversal, pane hit-testing, and SGR mouse parsing. Split/unified and wrap/clip formatting also has focused tests. The new Review Module may internalize these algorithms only after replacing legacy line anchors with exact Artifact Anchors and feeding the renderer immutable Snapshot evidence rather than a live patch.
- **Terminal interaction primitives.** The pure composer buffer in [`apps/tui/src/chat/composer.ts`](../apps/tui/src/chat/composer.ts), transcript/viewport arithmetic, terminal resize handling, pane-width normalization, keyboard focus conventions, and mouse enable/disable parsing are credible low-level mechanics. They provide evidence for editing, scrolling, and adaptive layouts. They do not validate Ink as the v1 renderer, the current pane composition, current bindings, accessibility, or the legacy Chat/Plan/Changes/Review information architecture; [Choose the terminal interaction system](./WF-012-choose-terminal-interaction-system.md) supersedes those product choices.
- **Fail-closed file and effect ordering techniques.** [`apps/tui/src/review/persistence.ts`](../apps/tui/src/review/persistence.ts) and [`apps/tui/src/review/receipts.ts`](../apps/tui/src/review/receipts.ts) validate input before replacement, create owner-only directories/files, write a same-directory exclusive temporary file, and rename it into place. [`apps/tui/src/review/submission.ts`](../apps/tui/src/review/submission.ts) records pending state before the external call, records terminal evidence before queue clearing, preserves source records on failures, and has explicit restart reconciliation tests. These are valuable regression seeds for Durable Commit ordering. The implementation is not itself a durable store: it has no transaction across files, `fsync`, writer lock, generation switch, quarantine, or concurrent lost-update protection.
- **Local stream framing and hardening.** [`apps/tui/src/bridge/server.ts`](../apps/tui/src/bridge/server.ts) and [`packages/pi-connector/src/socketClient.ts`](../packages/pi-connector/src/socketClient.ts) correctly handle split and coalesced newline-delimited frames, schema validation, 1 MiB bounds, handshake timeout, owner-only Unix socket permissions, stale-socket probing, registration ordering, disconnect cleanup, bounded exponential reconnect, and fatal protocol errors. Real Unix socket integration tests cover those mechanics. They may sit inside future process, Harness, or Editor Adapters; the multiplexed bridge and its protocol are not a v1 Seam.
- **Pi event wiring.** [`packages/pi-connector/src/index.ts`](../packages/pi-connector/src/index.ts) demonstrates supported extension hooks for session identity, current model/workspace, busy state, submission, abort request, text/tool observation, provider error detection, and settlement. [`packages/pi-connector/src/requestController.ts`](../packages/pi-connector/src/requestController.ts) provides useful single-flight and late-terminal-event regression scenarios. Only the hook wiring and tests are candidates. [Probe Pi’s attached-session guarantees](./WF-019-probe-pi-attached-guarantees.md) and [Probe Pi’s Plan Revision capture guarantees](./WF-025-probe-pi-plan-revision-capture.md) are stronger evidence than this connector’s lifecycle interpretation.
- **Build scaffold.** Strict TypeScript, `noUncheckedIndexedAccess`, NodeNext ESM, project-local declarations, pnpm workspace ordering, source-via-`development` conditions, and compiled import smoke tests are a credible baseline. They can support a replacement package topology without preserving today’s package seams.

Tests should move only with the behavior they still assert through a new Module Interface. Pure algorithm, temporary-Git, Unix-socket framing, persistence validation, and effect-ordering tests have the highest leverage. Tests of legacy record states, prompt wording, global modes, generic capability Booleans, or `done` semantics are historical evidence rather than transplant candidates.

### Delete rather than carry forward

- Delete `@neoflow/core` as a shared grab bag. Its exported context, path identity, Git, socket, and transport primitives force callers to assemble product behavior and destroy locality. Blueprint records and invariants belong to their owning deep Modules; low-level helpers remain private implementation.
- Delete `@neoflow/ai-harness`, `AiHarness`, `MockHarness`, generic mode requests, prompt-format authority, the current Harness protocol, and `HarnessConnectionManager`. The current Interface exposes provider-shaped streaming and broad Booleans while hiding none of the truth-critical Handoff, Capability Snapshot, route, start, terminal, interruption, and unresolved semantics the Harness Interaction Module must own.
- Delete the monolithic [`apps/tui/src/App.tsx`](../apps/tui/src/App.tsx) orchestration, global mode/focus/workspace derivation, in-memory transcripts and Plan artifact, ambient attachment scope, UI-owned Git watchers, production Mock fallback, and pure-black Codex treatment. UI surfaces must issue semantic commands and consume projections; they must not create stores, run Git, construct Harness messages, or infer the active Workspace from the latest context item.
- Delete the live-diff Review model, mutable annotation queue semantics, mutable receipt outcome model, generated review prompts, auto-clearing-on-Harness-settlement behavior, and 512 KiB all-or-nothing diff limit. Selective parser, anchor-display, and navigation implementation may be transplanted, but none of these records can become canonical Review records.
- Delete normalized real paths as Workspace Identity and every caller-visible `getGitRoot`/`getGitDiff` composition. The complete endpoint, manifest, capture, revalidation, and per-file degradation rules in [Define the workspace and change-set evidence contract](./WF-023-define-workspace-change-set-evidence.md) require a deeper Module.
- Delete `neoflow send`, `ContextMessage`, `ContextItem`, `AiIntent`, one-shot Neovim commands and compatibility aliases, bridge multiplexing, and TUI process-spawn navigation. The current Neovim integration is outbound-only, shell-command based, unacknowledged, unversioned, and untested; it supplies no Editor Attachment Identity, buffer revalidation, command idempotency, persistent status, or bidirectional navigation required by [Shape the editor-companion workflow](./WF-009-shape-editor-companion-workflow.md).
- Delete repository-local `.neoflow/review.json` authority and the separate mutable receipt store. Preserve legacy bytes for import, but do not layer new Authoritative Workflow State around these formats.
- Do not preserve today’s five-package graph merely because it builds. In particular, tracked `node_modules` symlinks, all-private package manifests, and current source-condition exports are development mechanics, not release topology.

### Constraints the target Module architecture must absorb

**Runtime, build, and packaging**

- The repository is ESM (`NodeNext`, ES2022) and pnpm-workspace based. The lock resolves Ink `5.2.1`, React `18.3.1`, Commander `12.1.0`, TypeScript `5.9.3`, and Pi coding agent `0.80.6`. The Pi package declares Node `>=22.19.0`, while Neoflow declares no `engines` or checked-in Node version. The plan must choose and declare one Node floor rather than inherit the successful Node 24 workstation implicitly.
- Every package is private. Current release evidence is limited to compiled imports and CLI `--help`; there is no package/installer test, clean-machine setup test, TUI launch smoke, Neovim test, uninstall/upgrade path, or CI/platform matrix. The package topology remains genuinely open.
- Builds use Unix commands (`rm -rf`), and runtime code uses Unix sockets and `/dev/null`. This is compatible with the blueprint’s native macOS, Linux, and single-environment WSL2 support, but not native Windows. Platform-specific Adapter code must stay local rather than leaking into workflow Interfaces.
- Ink and React are the only TUI runtime dependencies, Commander the only CLI framework, and no database/storage dependency exists. Existing dependencies therefore do not constrain the persistence or renderer choices; those choices need their own evidence.

**Process and locality**

- Today the TUI process simultaneously owns UI state, the single global socket, Git watching, legacy persistence, and Harness routing. If the TUI exits, all attachment reachability disappears. The one socket path permits one server for the user, while the blueprint requires one Workspace Writer per Workspace Identity with other processes connecting or remaining read-only. The runtime decision must deliberately place writer ownership, multi-workspace routing, process lifetime, and TUI restart behavior.
- Persistence is synchronous load-modify-save JSON with an implicit single in-process writer. Concurrent processes can overwrite one another, and two files approximate one semantic transition. The Authoritative Workflow State Interface must supply atomic semantic transitions and make competing writes impossible rather than relying on UI discipline.
- Recursive `fs.watch` with a non-recursive fallback is refresh convenience, not evidence. Linked worktrees, unstable reads, scope-specific relevance, and missing Git/filesystem facts require explicit capture and revalidation inside the workspace-evidence Module.

**Harness and editor integration**

- The checked-in Pi Adapter targets extension types `0.80.6`; the stronger Plan-capture probe covers `0.80.10`. A peer range of `>=0.80.6` is too broad to establish compatible guarantees by itself. Adapter compatibility, Capability Manifest versioning, and contract probes must accompany supported Pi versions.
- The current connector emits `accepted` before `sendUserMessage`, has no observed-start timeout, treats local cancellation intent plus eventual settlement as cancelled, converts disconnect into terminal failure, loses active correlation on reconnect, and hard-codes broad `chat`/`plan`/`review` capability Booleans. Pi actually requires separate submission, observed start, final stored assistant content, settlement, cancellation-race, session-epoch, and unresolved evidence. These facts belong behind the Harness Interaction Module’s small semantic Interface, never in Planning or Reviewing.
- Current stream text is a display projection, not exact Artifact content. Plan Revision capture must use the selected finalized structured assistant value plus independent settlement evidence, a lossless encoding, durable correlation, and fail-closed ambiguity handling as settled by [Probe Pi’s Plan Revision capture guarantees](./WF-025-probe-pi-plan-revision-capture.md).
- The current bridge identifies a Harness by self-reported session id plus normalized path and silently replaces the previous peer. The target needs discovered candidates, validated Attachment Identity, canonical checkout evidence, one-flight rules, route-specific capabilities, and conservative reconnect. The current Neovim code supplies no credible persistent Companion Seam, so that Adapter begins as a replacement rather than an extension.

**Workspace evidence and legacy data**

- `getGitDiff` captures only `HEAD` to effective working state, buffers the whole patch, globally rejects over 512 KiB, and has no complete manifest, exact endpoint records, file-side availability, digests, race revalidation, scoped staleness, or per-file degradation. It does not cover the blueprint’s comparison matrix, 1,000-file/50 MiB floor, sparse/partial repositories, arbitrary Git path bytes, symlink bytes, Gitlinks, large-file indirection, missing objects, or Implementation Baselines. Its stable command options are useful, but its Interface and result are insufficient.
- The ignored workspace currently contains a version-2 `.neoflow/review.json` with seven legacy annotations. The parser also accepts raw version-1 arrays and version-1 objects. Writers replace with version 2. This proves the one-time importer must discover real repository-local legacy state, preserve its original bytes, reject malformed or newer data conservatively, and turn pending entries only into human-confirmed migration candidates after a new Review Snapshot exists.
- Legacy receipt files are version 1 under `${XDG_STATE_HOME:-~/.local/state}/neoflow/workspaces/<sha256(realpath)>/review-receipts.json`; they embed the old absolute workspace, retain at most 100 terminal batches, and mutate pending/outcome/queue-disposition state. A symlink alias shares a path, but a workspace move changes the hash and can orphan discovery. Import cannot equate those mutable batches with canonical Commitment Receipts; it must preserve any found records as labelled read-only legacy history and account for old-path lookup.
- Temp-file rename and `0600`/`0700` permissions are useful implementation techniques, but they do not establish the blueprint’s Durable Commit, migration generation, Receipt Integrity, recovery quarantine, or no-semantic-pruning guarantees. [Set persistence, portability, and recovery policy](./WF-010-set-persistence-portability-recovery-policy.md) remains authoritative.

The audit introduces no additional decision ticket. Its findings sharpen the already-open target-architecture, runtime, state, Harness, TUI, Editor, migration, verification, and packaging tickets. The next architecture decision should use the credible mechanics only as private candidate implementation and should make every replacement Seam from blueprint ownership and truth-critical invariants first.
